## 最高优先级：分数可信度

### 多 trial 取平均 + 方差
- **问题**：现在每个 模型×任务 只跑一次。LLM 输出有随机性（尤其 temperature>0），单次分数噪声大——两模型差 0.3 分可能只是抽样噪声，不是真实差距。
- **方案**：每个 combo 跑 N 次（可配 3-5），分数取均值，展示标准差 / 置信区间。运行评测页加 trial 数配置；Result 表加 trial 序号或新建 trial 子表；汇总按均值排序并显示 ±σ。
- **价值**：整个 benchmark 结论的统计可信度基础。第一优先。

### 开放型改用两两对比（pairwise）而非绝对 1-5 档
- **问题**：人给绝对分不稳——今天的"4 档"和明天不是一个尺度，跨任务也无法比较。这是当前方法论最大的弱点。
- **方案**：盲评改为每次并排出两份、选更好的（或平局），用 Bradley-Terry / ELO 反推排名。盲评 UI 已有，改成成对呈现改动不大。
- **价值**：人的相对判断远比绝对打分可靠，且更省脑力。方法论上最想改的一项。

### LLM-as-judge（与人评互补）
- **问题**：开放型全靠人评，量一大评不动。
- **方案**：复用"评测生成模型"当 judge 自动打分，人只抽查 / 复核分歧项。
- **注意**：judge 有自我偏好偏差（易给同家族模型高分），只做**初筛 + 人工兜底**，不能完全替代人评。

## 次高：让结果产生洞察

### 统计图表（req.md 里标注的 TBA）
- 各模型跨维度雷达图；单维度排行榜（含 ±σ）。

### 成本追踪
- 记录每次调用的 token 数，换算成本（$）。比较模型时"贵一倍只好 2%"是关键决策信息，当前完全缺失。

## 数据完整性（现有隐患）

### 任务版本化
- **问题**：编辑任务 prompt 后，历史结果仍挂在同一任务上，但它们是用旧 prompt 跑的，**变得不可比却看不出来**。
- **方案**：编辑时把 prompt 快照进 Result；或禁止编辑已被评测引用的任务，改为"复制新建"。越晚补，迁移越麻烦。

### 任务删除引用检查
- 删除被评测引用的任务会让历史结果变孤儿。删除前检查引用，或软删除。

## 运维体验

### 结果导出
- CSV / Markdown 报告，便于存档与对外分享。
