## 07月23日 21:15

### 需求描述

为 PLLM Benchmark（个人用 LLM 评测工具）确立面向工具型应用的界面设计规范，并通过可交互的前端 demo 验证视觉与交互方向。原有 DESIGN.md 是为营销落地页/个人主页编写的（Hero 区、大字号、疏朗留白、低信息密度），不适配数据密集的工具型 Web 应用。

### 背景与目标

项目是数据密集的工具型 Web 应用，最终技术栈为前端原生 JS + TailwindCSS、后端 FastAPI。界面需要在单屏承载大量结构化信息（模型列表、维度白名单、评测进度矩阵、多路输出打分），因此设计基调要从"营销页少即是多"转向"工具型高信息密度"。目标是产出一份能直接指导后续所有页面开发的界面规范，并用真实可点的 demo 让设计方向落地确认，避免只停留在文字描述。

### 功能详情

#### 整体设计基调（已确认）

- 工具型高信息密度：单屏信息量优先，间距收紧到工具尺度（4/8/12/16/24px），留白只用于分组分隔而非烘托氛围。
- 白色极简配色：纯白背景、黑灰文字、低饱和边框（`rgba(0,0,0,0.08)` 一类）；整屏近乎黑白灰，彩色只承载状态语义（success/error/warning/info/neutral 五种低饱和语义色）。
- 左侧导航布局：固定左侧侧边栏（220px）+ 顶部条（56px，页面标题 + 主操作）+ 主内容区的经典工具应用框架，所有页面统一遵循。
- 字号工具尺度：去掉 36–72px 营销字号，正文/表单/表格统一 13px，密集数据 12px，微标签 11px，页面标题 18px；URL/JSON/数值一律等宽字体便于扫读比对。
- 克制动效：200–300ms、ease-out；hover 只做颜色过渡不做位移，浮层用淡入/滑入，streaming 用逐字追加 + 光标闪烁。

#### 已确认的 4 个页面关键交互

1. 模型管理页（Chat 模型）
   - 数据表格：斑马纹 + 行 hover + 名称/URL/模型名/状态/操作列，数值与等宽字段对齐。
   - 状态标签：可用（success）/ 不可用（error）/ 未测试（neutral）/ 测试中（info + spinner）；不可用标签 hover 显示失败原因 tooltip。
   - "测试可用性"按钮：点击后状态切为"测试中"spinner，结果回来再更新标签。
   - 新增/编辑走右侧抽屉 Drawer 表单：显示名称、API base URL、API key、模型名、默认参数 JSON（等宽多行输入），底部右对齐"取消 / 保存"。

2. 维度管理页
   - 维度列表为可展开卡片，收起时显示维度名、描述、任务数、绑定模型数。
   - 展开后显示 system_prompt 预览 + 模型白名单多选（自定义 Checkbox 勾选加入/移除评测范围）。
   - 新增/编辑维度走 Drawer 表单：名称、描述、system_prompt 多行文本域，附评测时作为 system 消息拼接的说明。

3. 评测运行页
   - 顶部总进度条 + "已完成 n / 总数 N"计数（等宽）。
   - 任务 × 模型组合矩阵，逐个执行；进行中的组合状态为 streaming 并逐字打出输出文本（光标闪烁），组合卡片高亮。
   - 每条完成后显示 TTFT、字符/秒、字符数指标；状态标签在 等待中 / streaming / success / cancelled 间切换。
   - 顶部"取消评测"按钮：二次确认后中断，已完成结果保留，进行中与未开始组合标记为 cancelled，顶部场次状态 badge 从 running → done / cancelled。

4. 盲评打分页
   - 顶部任务说明 + rubric 区，明确评分区间与"忽略模型身份、仅看文本质量"。
   - 某开放型任务下多个模型输出随机打乱、隐藏模型名，展示为"输出 A / B / C"卡片。
   - 每卡片下方 1–5 分段按钮打分控件，选中态黑底白字；顶部实时显示已打分计数。
   - 全部打分完成后底部"提交打分"按钮激活；提交时（结果页）才揭晓输出与模型的对应关系。

### 设计决策

- DESIGN.md 定位为界面开发规范：已原地重写为面向工具型高信息密度应用的规范，保留原有好基调（白色极简配色、低饱和边框、克制动效原则、主按钮黑底白字 + Ghost 次级按钮、卡片圆角与线性图标），重写信息密度、字号层级、间距体系，并补齐工具组件规范（数据表格、表单控件、状态标签、进度条/Spinner/骨架屏、Modal/Drawer、评分控件、左侧导航 + 顶部条布局）。后续所有页面开发以 DESIGN.md 为准。
- demo 用原生 HTML + TailwindCSS（CDN）+ 少量原生 JS 实现，纯 mock 数据不接后端，仅用于验证视觉与交互方向，位于 `demo/` 目录，`demo/index.html` 为入口。
- 编辑类操作统一用右侧 Drawer（模型、维度），保留列表上下文不打断；破坏性操作（删除、取消评测）需二次确认。

### 默认决策（已确认，无需再出 demo）

1. 图片生成模型管理页复用 Chat 模型管理页的同一套设计规范（表格 + 状态标签 + 测试可用性 + 抽屉表单），开发时按同一模式实现即可，不单独出 demo。
2. 评测运行页 demo 中的 streaming 速度、进度节奏为纯演示值；实际指标口径以概要设计文档为准——TTFT（首字响应时间）+ 总生成耗时 + 字符/秒（`len(output_text) / 总生成时间`，不做中英文加权），不使用 token 计数。
